Ultra-Peripheral Collisions

Ultra-peripheral collisions (UPC) are hadron--hadron collisions at impact parameters large enough that the strong interaction is suppressed while the electromagnetic field of one beam supplies a quasi-real photon. In Sartre, the photon interacts diffractively with the other beam particle to produce an exclusive vector meson. The current UPC workflow is therefore the exclusive Sartre generator and examples/sartreMain.cpp, not SartreInclusiveDiffraction.

Scope and physics treatment

UPC mode produces exclusive vector-meson final states, schematically h1 + h2 → h1′ + h2′ + V. Sartre samples the momentum transfer t and the pomeron momentum fraction xℙ, rather than the Q2 and W variables used for electron--hadron diffraction. The UPC cross-section path uses transverse photon polarization; generated UPC events have Q2 = 0.

The photon flux accounts for the electromagnetic field of a proton or nucleus and includes the no-hadronic-interaction probability. For coherent UPC production, Sartre evaluates the contributions associated with the two photon-source directions, including their interference. Incoherent production is also available when suitable variance tables are present. Nuclear breakup through the Gemini++ path is currently unavailable in UPC mode; Sartre switches enableNuclearBreakup off during initialization.

Inclusive diffraction: Sartre 2 adds inclusive diffraction for ep and eA, but UPC is not its supported inclusive workflow. Keep UPC = false in an inclusive-diffraction runcard.

UPC runcard settings

Set UPC = true in an otherwise exclusive runcard. In UPC mode the historically named electron-beam settings are repurposed for the second hadron beam. The convention is fixed by the generator:

Setting
Meaning in UPC mode
UPC = true Enables hadron--hadron UPC kinematics and the nuclear photon flux.
A Mass number of hadron 1, the positive-z beam and the target represented by the primary amplitude tables. Use 1 for a proton.
UPCA Mass number of hadron 2, the negative-z beam. It supplies the photon flux in the generator convention. Use 1 for a proton.
hBeamEnergy Energy of hadron 1 in the positive-z direction.
eBeamEnergy Energy of hadron 2 in the negative-z direction. The name is retained for runcard compatibility; it is not an electron beam in UPC mode.
vectorMesonId PDG identifier of the exclusively produced vector meson.
xpomMin, xpomMax Optional requested range in xℙ. Sartre intersects it with the available table and physical ranges.
applyPhotonFlux Leave enabled for event generation. Disabling it is an expert-only cross-section study option.

For example, a symmetric Pb--Pb setup begins with the following runcard fragment. Beam energies must match the desired collision system and the table coverage.

# Exclusive UPC configuration: Pb + Pb
UPC = true
A = 208
UPCA = 208

# Hadron 1 (+z) and hadron 2 (-z) energies
hBeamEnergy = 100
eBeamEnergy = 100

vectorMesonId = 443
dipoleModel = bSat
applyPhotonFlux = true

# Optional; leave disabled to accept the available UPC table range
# xpomMin = 1e-5
# xpomMax = 1

The complete definitions and defaults are in the runcard reference. The initialization printout identifies both UPC beam species, their four-vectors, the model, and the resolved kinematic range; retain it with production output.

Beam orientation and symmetric beams

Sartre stores hadron 1 (A) in the positive-z direction and hadron 2 (UPCA) in the negative-z direction. Thus the photon-emitting beam in the event record is initially always the beam arriving from the right in the usual beam-line drawing. For identical beams, an analysis should populate both physically equivalent orientations.

The distributed sartreMain.cpp does this by randomly reversing every four-vector in half of the UPC events when A == UPCA. A rotation by π about the x axis implements the reflection in the xy plane:

if (settings->UPC() && settings->A() == settings->UPCA())
    randomlyReverseBeams(event);

void randomlyReverseBeams(Event* event)
{
    if (EventGeneratorSettings::randomGenerator()->Uniform(1) > 0.5) {
        for (unsigned int i = 0; i < event->particles.size(); ++i)
            event->particles.at(i).p.RotateX(M_PI);
    }
}

Copy this step into a custom UPC driver if it needs the same symmetric acceptance. It changes the event orientation only; it must not be used as an additional event weight.

Asymmetric beams and normalization

For an asymmetric system, such as proton--gold, the two photon-emitter/target assignments are physically different. Generate and analyze the two configurations separately:

  1. A = 1, UPCA = 197: photon emitted by gold and scattering from the proton;
  2. A = 197, UPCA = 1: photon emitted by the proton and scattering from gold.

Combine the resulting samples using their respective calculated cross sections and generated event counts. The table set must match the target selected by A in each run. Experimental selections may make one contribution dominant, but that should be demonstrated for the particular observable and phase-space cuts.

Normalization caution: the Sartre 1 page instructed users to multiply the symmetric-beam total cross section by two. The current UPC implementation already evaluates contributions from both photon-source directions in its coherent treatment, and the shipped sartreMain prints Sartre::totalCrossSection() without an additional factor. Do not apply a universal manual factor of two. Validate the normalization for the chosen collision system, table set, rapidity convention, and observable against a reference calculation before applying any external factor.

Tables, event record, and checks

UPC amplitude tables differ from ordinary exclusive ep/eA tables: they are two-dimensional in t and xℙ. UPC table generation uses tmin, tmax, tbins, xmin, xmax, and xbins. Table production and merging are expert tasks; inspect delivered tables with tableInspector and query them with tableQuery, which prompts for t and xℙ for UPC tables. See Table Tools and Tables.

UPC events use the ordinary Event and Particle records. Before the exclusive final-state calculation, the generator sets Q2, Bjorken x, and W to zero and marks the photon transverse; the final-state generator completes the UPC kinematics. Use event->list() for a few events whenever a custom program changes the record or applies beam reversal.

Production checklist

  • Use Sartre and an exclusive vector-meson runcard, with UPC = true.
  • Verify that every required UPC table covers the generated t and xℙ range.
  • Keep applyPhotonFlux = true unless performing a documented expert-only calculation.
  • For symmetric beams, retain the random event reversal used by sartreMain.
  • For asymmetric beams, generate the two target/emitter assignments separately and normalize them deliberately.
  • Record the runcard, random seed, table identities, and initialization output with the event sample.

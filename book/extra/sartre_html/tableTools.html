Tables and Table Tools

Why Sartre uses tables

Sartre generates events from precomputed amplitude or cross-section tables. Calculating the required integrations at every phase-space point during event generation would be too slow. The tables therefore hold the information needed to evaluate cross sections and sample events efficiently.

Generating tables is computationally demanding and requires care in choosing physics settings, phase-space ranges, binning, and numerical controls. It is intended for expert users. Most users should use a matching provided table set rather than generate a new one.

Every Sartre event-generation run requires tables compatible with its target, dipole model, process, and other settings. A missing or mismatched table set prevents the intended calculation from running correctly.

Obtaining table sets

Many table sets are provided separately from the source distribution. The installed getSartreTables.py utility downloads a compatible published set from the Sartre table server. Run the copy in $SARTRE_DIR/bin/ (or /usr/local/sartre/bin/ for the default installation), not a copied script elsewhere: it identifies the destination from its installed location. Use getSartreTables.py list to see the catalog, then select a set with, for example, getSartreTables.py --sys=ePb --sat=bSat --part=phi --set=KMW. The selection is case-insensitive; add --upc for a UPC set, while --part=X selects inclusive-diffraction tables. SARTRE_DIR is an optional explicit override.

After installation, tables belong under the Sartre table directory:

$SARTRE_DIR/tables/

For a default installation this is normally /usr/local/sartre/tables/.

Table directory hierarchy

The directory hierarchy identifies the physics configuration. Sartre locates tables by their directory placement; do not flatten or rename the hierarchy when copying a table set.

tables/
├── 1/                     # proton target
│   ├── bSat/
│   │   ├── 333/             # exclusive φ production
│   │   ├── 443/             # exclusive J/ψ production
│   │   └── X/               # inclusive diffraction
│   └── bNonSat/
│       └── ...
├── 197/                   # nucleus with A = 197
│   ├── bSat/
│   └── bNonSat/
└── 208/                   # nucleus with A = 208
    └── ...

The levels are:

  • Target directory: 1 for a proton, or the nuclear mass number A for a nuclear target.
  • Dipole-model directory: bSat or bNonSat.
  • Process directory: the PDG particle identifier for exclusive vector-meson or DVCS production (for example, 333 for the φ meson), or X for inclusive diffraction.

The process directory contains all ROOT table files required by that calculation. Their filenames carry additional bookkeeping information, but Sartre reads the table content and relies primarily on the hierarchy above. A complete process directory can occupy substantial disk space.

Table generation

The distribution contains tableGeneratorMain.cpp for exclusive tables and tableGeneratorInclusiveDiffractionMain.cpp for inclusive-diffraction tables. Their runcards define the target, dipole model, phase-space range, and binning. See the Runcard Reference for the settings, particularly the inclusive betamin, betamax, zmin, zmax, betabins, and zbins parameters.

Table generation is an expert workflow. Before producing a substantial set, verify the intended settings and table hierarchy with the maintainers or against an existing compatible set. The Table Generator Guide describes the supplied programs, work splitting, DFT/FFT path, merging, and validation expectations; parts of the complete Sartre 2 production procedure remain TBD.

Table tools

When Sartre is built with the default SARTRE_BUILD_TOOLS=ON option, the following command-line tools are installed in $SARTRE_DIR/bin. They operate on binary ROOT table files. Most are intended for expert table production or maintenance; tableInspector is generally useful for checking a downloaded table before a run.

Table Tool Documentation

tableInspector

Inspects one or more tables and prints their metadata, dimensions, and kinematic coverage. This is the generally useful tool for ordinary users: run it after downloading or copying a table set to verify that the table has the expected target, process, dipole model, and range.

tableInspector [-v] [ -x bin -y bin [-z bin [-w bin]] | -g bin | [-a] [-s] [-b] | -e txt] file(s)
-vPrint extra diagnostic output.
-bPrint the table identifier in binary form first.
-aPrint the position and value of every table cell.
-sPrint content statistics, including extrema and empty bins.
-g binConvert a global bin number to ROOT/table-bin coordinates.
-x bin -y bin [-z bin [-w bin]]Convert ROOT/table-bin coordinates to a global bin number.
-e txtPrint one metadata element: A, pol, cont, vmid, vmstr, model, pset, type, hotspots, fock, or quark.

tableDumper

Exports the complete content of one Sartre table to a new binary data file. It refuses to overwrite an existing output file.

tableDumper [-v] table_file binary_file

Use -v for additional diagnostics while writing. This is principally an expert export and debugging tool.

tableMerger

Merges compatible table files, including partially filled tables. It checks table integrity and writes merged output named <prefix><ID>_merged.root. Inspect the resulting files with tableInspector.

tableMerger [-n] [-0] [-p prefix] [-m] file(s)

-n performs all checks without writing output and should be used first. -0 ignores zero-content bins, which is useful for partially filled inputs. -p selects an output prefix, and -m lists missing bins.

tablePriority

Lists or changes a table's embedded priority. Priority is part of the table identifier and controls precedence when otherwise matching table candidates are available. Changing a priority rewrites the supplied table file, so use it only for deliberate table-set maintenance.

tablePriority [-s priority] [-f] file(s)

Without -s, the tool lists priorities. -s priority sets a new priority from 0 through 255. -f includes the filename in the output.

tableQuery

Interactively evaluates and prints interpolated values from one or more tables. It prompts for the relevant coordinates and identifies results outside a table's stored range. This is useful for checking interpolation and coverage.

tableQuery file(s)

For exclusive tables it prompts for t, Q2, and W; for UPC tables it prompts for t and xℙ; and for inclusive tables it prompts for Q2, W, β, and z.

tableVarianceMaker

Creates an exclusive variance_A table from compatible mean_A2 and mean_A input tables. It verifies that the two inputs agree in their physics metadata and binning before continuing. Inclusive-diffraction tables are not supported by this tool.

tableVarianceMaker [-n | -o output] file_mean_A2 file_mean_A

-n checks the inputs without creating output. -o output writes the result to the named ROOT file. Without either option, the generated content is written to standard output. Run the no-output check first and inspect a generated table with tableInspector.
